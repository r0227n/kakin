# Kakin アプリ仕様

## 1. 目的と範囲

Kakin は推し活のお金を管理するスマホアプリです。
毎月決めた**推し活代**を予算とし、チケット代・ドリンク代・チェキ代などの**支出**を記録して、月ごとの**残高**を繰り越しながら確認します。
チケット代は Gmail に届く購入メールから自動で転記し、ドリンク代やチェキ代は手で入力します。
チケットの抽選への申込からチケットの確保までを**チケット申込**として追い、申込締切・当落発表・入金期限をスマホの通知でリマインドします。

この文書はアプリが「何をするか」の正（SSOT）です。
実装方式・DB スキーマ・画面の細部は書きません。
[DB.md](DB.md)・画面仕様・コードと食い違う場合はこの文書を優先し、食い違う側を合わせて直します。
用語の正は [GLOSSARY.md](../GLOSSARY.md) です。

## 2. 前提

| 項目             | 決定                                                     |
| ---------------- | -------------------------------------------------------- |
| 対象端末         | iOS と Android のスマホ                                  |
| 利用者           | 1人。ログインやユーザー登録はない                        |
| データの保存先   | 端末内のみ。サーバーは持たない                           |
| Gmail アカウント | 1つだけ連携できる                                        |
| 通貨             | 日本円のみ。金額は円単位の整数                           |
| 時間帯           | 日本時間のみ。「日」「月」は日本時間の暦日・暦月で区切る |
| 収入             | 扱わない。お金の入りは推し活代だけ                       |
| 通知             | チケット申込のリマインドだけを出す（7.3）                |

## 3. お金のモデル

### 3.1 推し活代

推し活代は、推し活に使ってよい1ヶ月あたりの予算額です。

- 推し活代は**開始月**と**月額**で設定します。開始月から毎月、月額が残高に加わります。
- 月額を変更すると、変更した月から新しい月額を使います。それより前の月の推し活代は変わりません。
- 開始月以降の任意の月について、その月だけの推し活代を上書きできます（ボーナス月の増額など）。上書きを解除すると、その月は月額に戻ります。
- 推し活代は0円以上の整数です。

### 3.2 残高と繰越

各月の残高を次の式で求めます。

```text
残高 = 繰越 + その月の推し活代 − その月の支出合計（支払日で計上）
繰越 = 前月の残高（開始月の繰越は 0）
```

- 残高がマイナスになっても、そのまま翌月へ繰り越します。翌月に使える額はその分だけ減ります。
- 残高の計算には常に**支払日**を使います。後述の計上基準を切り替えても、残高は変わりません。
- 開始月より前の支払日の支出は、一覧には表示しますが残高には含めません。
- 支出を追加・編集・削除すると、その支払日の月とそれ以降のすべての月の残高が変わります。

例: 推し活代が月 30,000 円で、11月に3月公演のチケット代 12,000 円を含む 45,000 円を払った場合

| 月   | 繰越    | 推し活代 | 支出   | 残高    |
| ---- | ------- | -------- | ------ | ------- |
| 11月 | 0       | 30,000   | 45,000 | −15,000 |
| 12月 | −15,000 | 30,000   | 10,000 | 5,000   |

3月公演のチケット代は、公演のある3月ではなく、払った11月の残高から引かれます。

### 3.3 推し活代が未設定のとき

推し活代を設定するまでは、推し活代・繰越・残高を表示せず、支出合計だけを表示します。
支出の記録や Gmail の自動転記は、推し活代を設定しなくても使えます。

### 3.4 立替・返金・中止

収入を持たないため、お金の戻りは支出の金額を変えて表します。

- 友人の分を立て替えた場合は、全額を支出として記録します。回収した後で、自分の負担分の金額に編集します。
- 公演が中止になって返金された場合は、返金後の額に編集するか、支出を削除します。
- どちらの場合も、元の支払日の月から後の残高が変わります。

## 4. 公演

公演は、日時と場所が決まった、チケットの対象となるイベントです。

| 項目     | 必須 | 内容           |
| -------- | ---- | -------------- |
| 公演名   | 必須 | 空にはできない |
| 開始日時 | 必須 | 日付と時刻     |
| 会場     | 任意 | 会場名         |

- 1つの公演の開始日時は1つです。フェスの2日通し券のように複数日にまたがる場合は、初日の公演として登録します。
- 公演は手で登録するか、Gmail の自動転記で作られます。
- 公演を削除すると、その公演が必須の支出（チケット代・ドリンク代・チェキ代）と、その公演のチケット申込を一緒に削除します。その公演が任意の支出は削除せず、公演との紐づけだけを外します。削除の前に、消える支出の件数と合計額、消えるチケット申込の件数を表示して確認します。

## 5. 支出

### 5.1 カテゴリ

支出のカテゴリは次の固定7種類です。ユーザーがカテゴリを追加することはできません。

| カテゴリ         | 公演 | 追加の項目           |
| ---------------- | ---- | -------------------- |
| チケット代       | 必須 | -                    |
| ドリンク代       | 必須 | -                    |
| チェキ代         | 必須 | チェキ相手・撮影枚数 |
| グッズ代         | 任意 | -                    |
| 交通費           | 任意 | -                    |
| コインロッカー代 | 任意 | -                    |
| その他           | 任意 | -                    |

### 5.2 項目

| 項目     | 必須                  | 内容                                      |
| -------- | --------------------- | ----------------------------------------- |
| カテゴリ | 必須                  | 5.1 の7種類のいずれか                     |
| 金額     | 必須                  | 0円以上の整数。手数料を含め実際に払った額 |
| 支払日   | 必須                  | お金を払った日。日付だけで時刻は持たない  |
| 公演     | カテゴリによる（5.1） | 紐づける公演                              |
| メモ     | 任意                  | 自由記述                                  |

- 支払日には、クレジットカードの引き落とし日ではなく決済した日を入れます。
- 支払日と公演の開始日時は別の値です。今月払った数ヶ月後の公演のチケット代は、支払日が今月、公演が数ヶ月後になります。

### 5.3 チケット代

- 1つの公演の支払いごとに1件の支出として記録します。Gmail から自動転記したチケット代も1件の支出です。
- 同じ公演に2件以上のチケット代を記録できます。

### 5.4 ドリンク代

- 公演を選ぶと、前回登録したドリンク代の金額が最初から入力されています。そのまま登録すれば、追加の入力なしで済みます。
- 初めて登録するときは金額欄が空です。

### 5.5 チェキ代

- チェキ相手・撮影枚数（1枚以上）・単価（0円以上）を入力すると、金額を「撮影枚数 × 単価」で計算します。
- 計算された金額は直接書き換えられます。保存するのは金額と撮影枚数で、単価は保存しません。
- チェキ相手は登録済みの相手から選ぶか、その場で新しく登録します。同じ名前の相手を複数登録でき、所属（グループ名など）で見分けます。
- チェキ相手は専用の選択画面で、登録済みの一覧（最近撮った相手、所属ごと）や名前・所属の検索から選びます。
- 一度に複数のチェキ相手を選べます。単価は全員で共通にし、相手ごとに撮影枚数を入れて、相手ごとに1件ずつチェキ代を記録します。
- チェキ相手は名前・所属（任意）・アイコン画像（任意）を持ちます。アイコン画像は、登録するときか、選択画面から開く編集画面で設定します。
- アイコン画像は、その場で写真を撮るか、写真ライブラリから選びます。正方形に切り抜いて丸く表示します。アイコン画像がない相手は名前の頭文字を表示します。
- アイコン画像はこの端末の中だけに保存し、外部には送りません。画像を外したり差し替えたり、チェキ相手を削除したりすると、元の画像のファイルも消します。
- 編集画面では名前・所属・アイコン画像を変えられます。チェキ代の記録がない相手だけ削除できます。

### 5.6 編集と削除

- 支出はいつでも編集・削除できます。削除の前に確認します。
- Gmail から自動転記した支出も、手入力の支出と同じように編集・削除できます。

## 6. Gmail 自動転記

### 6.1 対象

チケットサービスごとに、次の種類のメールを取り込みます。

| メールの種類 | 内容                                         | 取り込みの結果                                           |
| ------------ | -------------------------------------------- | -------------------------------------------------------- |
| 申込受付     | 抽選の申込を受け付けた                       | 結果待ちのチケット申込（6.5）                            |
| 当選         | 抽選に当選した。入金期限が書かれることがある | 入金待ちのチケット申込。支払い済みなら確保済み（6.5）    |
| 落選         | 抽選に外れた                                 | 落選のチケット申込（6.5）                                |
| 決済完了     | 支払いが済んだ                               | チケット代の支出（6.2）と、確保済みのチケット申込（6.5） |

| チケットサービス | 決済完了の件名キーワード | 申込受付・当選・落選の件名キーワード |
| ---------------- | ------------------------ | ------------------------------------ |
| eplus            | 決済に関するご案内       | 未決定                               |
| ライブポケット   | 購入完了のお知らせ       | 未決定                               |

上記以外のチケットサービスのチケット代とチケット申込は手で入力します。

### 6.2 転記する内容

決済完了メールから公演情報を読み取り、確認を挟まずにチケット代の支出として登録します。

| 支出の項目 | 値                                                                   |
| ---------- | -------------------------------------------------------------------- |
| カテゴリ   | チケット代                                                           |
| 金額       | メールに支払総額があれば支払総額。なければ読み取れたチケット料金     |
| 支払日     | メールの受信日。コンビニ払いなどで実際の支払日とずれる場合は手で直す |
| 公演       | メールの公演名・開始日時・会場の公演                                 |

- 公演名と開始日時の両方が一致する公演がすでにある場合は、新しい公演を作らずにその公演へ紐づけます。一致する公演がなければ公演を新しく作ります。申込受付・当選・落選のメールでも、同じ規則で公演を決めます。
- 自動転記した支出には「Gmail から取り込み」の印を付けます。印は編集した後も残ります。
- 公演情報を読み取れなかったメールは登録しません。
- 一度取り込んだメールは、その支出・公演・チケット申込を削除した後も、再び取り込みません。

### 6.3 同期のタイミング

| 契機                 | 内容                                                                                                                                |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 手動                 | カレンダー・リストを下に引っぱる操作と、設定の「今すぐ同期」                                                                        |
| 定期バックグラウンド | 週1回を目安に実行する。結果待ち・入金待ちのチケット申込がある間は1日1回を目安にする。実行の時刻は OS が決めるため、遅れることがある |
| 初回連携             | 連携した時点から3ヶ月前までのメールをさかのぼって取り込む                                                                           |

アプリを開いただけでは同期しません。
当選メールは同期するまで取り込まれないため、入金期限のリマインドが遅れることがあります。

### 6.4 失敗と連携解除

- 同期に失敗した場合はアプリ内に表示します。通知は出しません。
- 認証の期限切れなどで再連携が必要な場合は、再連携の案内をアプリ内に表示します。
- 同期に失敗しても最終同期日時は更新せず、次の同期で取りこぼした範囲を取り込み直します。
- Gmail の連携を解除しても、取り込み済みの公演・支出・チケット申込は残します。

### 6.5 チケット申込の更新

申込受付・当選・落選・決済完了のメールから、チケット申込を作るか、段階を進めます。

1. 6.2 の規則で公演を決めます。
2. 更新するチケット申込を次の順で探します。
   1. メールの受付番号と同じ受付番号を持つチケット申込
   2. 同じ公演・同じチケットサービスで、落選・確保済みでないチケット申込のうち、最も新しく登録したもの
3. 見つからなければ、メールの種類に応じた段階でチケット申込を新しく作ります。

- Gmail は段階を先へ進めるだけで、前の段階には戻しません。チケット申込がメールより先の段階にあるときは、そのメールで何も変えません。
- 段階を進めるときは、メールにある受付番号・当落発表日時・入金期限を書き込みます。メールにない項目は変えません。
- 当選・落選・決済完了のメールの公演が、受付番号で見つけたチケット申込の公演と違う場合（第2希望で当選したときなど）は、チケット申込の公演をメールの公演に付け替えます。
- Gmail から作ったチケット申込や、Gmail で段階が進んだチケット申込にも「Gmail から取り込み」の印を付けます。

## 7. チケット申込

チケット申込は、ある公演のチケットを取るための1回の申込を、受付からチケットの確保まで追う記録です。
申込締切や入金期限を忘れないように、申込段階と期限を持ち、期限の前にスマホの通知でリマインドします。

### 7.1 申込段階

| 申込段階 | 意味                                   | 次に進む段階                 |
| -------- | -------------------------------------- | ---------------------------- |
| 申込予定 | 受付中で、まだ申し込んでいない         | 結果待ち・入金待ち・確保済み |
| 結果待ち | 抽選に申し込み、当落の発表を待っている | 入金待ち・確保済み・落選     |
| 入金待ち | 当選し、支払いを待っている             | 確保済み                     |
| 確保済み | 支払いが済み、チケットを確保した       | -                            |
| 落選     | 抽選に外れた                           | -                            |

- 先着販売のように抽選がない場合は、申込予定から入金待ちか確保済みへ直接進みます。
- カード決済などで当選と同時に支払いが済む場合は、結果待ちから確保済みへ直接進みます。
- 申込段階は手で自由に変えられます。前の段階に戻すこともできます。
- 発券の状況（発券待ち・発券済み）は段階として持ちません。必要ならメモに書きます。
- 段階はリマインドの通知とやること（9.4）からワンタップで進められます（7.4）。
- 入金期限を過ぎて無効になった申込や、取りやめた申込は削除します。

### 7.2 項目

| 項目             | 必須 | 内容                                                            |
| ---------------- | ---- | --------------------------------------------------------------- |
| 公演             | 必須 | 申し込む公演。複数の希望を出す抽選では第1希望の公演             |
| チケットサービス | 任意 | eplus・ライブポケット・その他                                   |
| 申込段階         | 必須 | 7.1 のいずれか                                                  |
| 受付番号         | 任意 | チケットサービスが申込に付ける番号。Gmail での照合に使う（6.5） |
| 申込締切         | 任意 | 日付と時刻                                                      |
| 当落発表日時     | 任意 | 日付と時刻                                                      |
| 入金期限         | 任意 | 日付と時刻                                                      |
| メモ             | 任意 | 自由記述                                                        |

- 1つの公演に複数のチケット申込を登録できます（先行と一般に別々に申し込む場合など）。
- 期限の時刻を入れないときは、申込締切と入金期限は 23:59、当落発表日時は 12:00 とします。
- チケット申込は金額を持ちません。払った金額はチケット代の支出として記録します（5.3）。
- 公演を削除すると、その公演のチケット申込も削除します（4）。

### 7.3 リマインド

期限は、チケット申込がその期限に関係する段階にあるときだけリマインドします。

| 期限         | リマインドする段階 | 通知するタイミング             |
| ------------ | ------------------ | ------------------------------ |
| 申込締切     | 申込予定           | 前日の 20:00 と、締切の3時間前 |
| 当落発表日時 | 結果待ち           | 発表日時ちょうど               |
| 入金期限     | 入金待ち           | 前日の 20:00 と、期限の3時間前 |

- 通知は端末内で予約します。サーバーは使いません。
- 申込段階・期限が変わったり、チケット申込を削除したりすると、予約済みの通知を取り消し、必要なら予約し直します。
- すでに過ぎたタイミングの通知は出しません。前日の 20:00 より後に登録した期限は、3時間前の通知だけになります。
- 通知には公演名と期限の種類・日時を出し、金額は出しません。
- 通知をタップすると、そのチケット申込を開きます。
- 通知には段階を進めるボタンを付けます（7.4）。
- 期限を過ぎても申込段階が変わっていないチケット申込は、アプリ内で段階の更新を促します。
- 設定で、期限の種類ごとにリマインドをオフにできます。
- 初めて期限を登録したときに、OS に通知の許可を求めます。許可されていない場合は、今後の公演の画面にその旨を表示します。

### 7.4 ワンタップでの段階の更新

段階を手で進め忘れると、済んだ期限の通知が届き続けます。そのため、期限ごとに次の段階へワンタップで進めるボタンを用意します。

| 期限         | ボタン      | 進む段階        |
| ------------ | ----------- | --------------- |
| 申込締切     | 申し込んだ  | 結果待ち        |
| 当落発表日時 | 当選 / 落選 | 入金待ち / 落選 |
| 入金期限     | 支払った    | 確保済み        |

- ボタンはリマインドの通知と、今後の公演のやること（9.4）に表示します。
- 通知のボタンはアプリを開かずに段階を進めます。
- やることのボタンで進めた直後は「元に戻す」を表示します。
- 先着販売で申込と同時に支払う場合など、表の段階以外へ進めるときは、チケット申込を開いて段階を選びます。
- ボタンでは期限や受付番号は変えません。入金期限を入れたい場合は、チケット申込を開いて入力します。

## 8. 計上基準

支出を「どの日・どの月のものとして見せるか」を、次の2つから切り替えられます。

| 計上基準 | 支出を置く日                                     |
| -------- | ------------------------------------------------ |
| 支払日   | 支出の支払日                                     |
| 公演日   | 紐づく公演の開始日。公演に紐づかない支出は支払日 |

- 初期値は支払日です。設定で初期値を変えられます。
- 切り替えはカレンダーとリストの見え方だけを変えます。推し活代・繰越・残高は常に支払日で計算します（3.2）。

## 9. 画面

画面下部のタブで次の4画面を切り替えます。

| タブ       | 役割                                                         |
| ---------- | ------------------------------------------------------------ |
| カレンダー | 月のカレンダーで、日ごとの支出と公演を見る                   |
| リスト     | 月ごとの支出を一覧で見て、残高を確認する                     |
| 今後の公演 | これから行く公演と、チケット申込の段階・近い期限を確認する   |
| 設定       | 推し活代・Gmail 連携・リマインド・計上基準の初期値を設定する |

カレンダーとリストには、支出を追加するボタンと計上基準の切り替えがあります。

### 9.1 月の概要

カレンダーとリストの上部に、表示中の月の概要を表示します。

- 推し活代・繰越・支出合計・残高（推し活代が未設定のときは支出合計だけ）
- 支出合計のカテゴリ別の内訳
- 残高がマイナスの月は、残高を警告の色で表示します。

計上基準が公演日のとき、支出合計と内訳は公演日で集計し、そのことをラベルで示します。推し活代・繰越・残高は支払日のままです。

### 9.2 カレンダー

- 月単位で表示し、前後の月へ移動できます。
- 各日に、その日の支出合計と、公演がある日の印を表示します。
- 日付をタップすると、その日の支出と公演の一覧を表示します。

### 9.3 リスト

- 表示中の月の支出を、日付の新しい順に並べます。
- 各行にカテゴリ・金額・公演名・日付を表示し、Gmail から取り込んだ支出には印を付けます。
- カテゴリで絞り込めます。

### 9.4 今後の公演

開始日が今日以降で、チケット代を1件以上記録した公演と、落選以外のチケット申込がある公演を表示します。
この画面には金額を表示しません。

- 上部に「やること」として、リマインドの対象になる期限（7.3）を近い順に並べます。期限を過ぎて段階が変わっていないチケット申込も含めます。各項目に段階を進めるボタンを付けます（7.4）。
- その下に公演を開始日時の早い順に並べ、各行に公演名・開始日時・会場・公演までの日数・チケット申込の段階を表示します。
- 公演をタップすると、その公演のチケット申込の一覧を表示し、チケット申込を追加・編集・削除できます。
- チケット申込を追加するボタンがあります。

### 9.5 設定

- 推し活代: 月額・開始月の設定、月ごとの上書き
- Gmail 連携: 連携と解除、最終同期日時、「今すぐ同期」、失敗時の再連携の案内
- リマインド: 申込締切・当落発表日時・入金期限それぞれのオンとオフ、OS の通知の許可の状態
- 計上基準の初期値

### 9.6 初回起動

初回起動時に、次の順で案内します。案内は一度最後まで進めると、次からは表示しません。

1. ようこそ: アプリでできること（推し活代での予算、会場での記録、チケット申込のリマインド）を紹介します。データは端末の中だけに保存し、登録やログインが要らないことを示します。
2. 推し活代の設定: 月額と開始月を設定します。スキップでき、後から設定画面で設定できます（3.3）。
3. Gmail 連携: 読み取るメールの種類と、メール本文を保存しないことを示してから連携します。スキップでき、後から設定画面で連携できます（6）。連携した場合は、初回連携の取り込み（6.3）をバックグラウンドで始め、終わるのを待たずに先へ進めます。

- 通知の許可は案内では求めません。初めて期限を登録したときに求めます（7.3）。

## 10. v1 の対象外

- バックアップ・エクスポート（端末を失うとデータも失われます）
- チェキ相手別・カテゴリ別の集計画面（月の概要にあるカテゴリ別の内訳は対象です）
- eplus・ライブポケット以外のチケットサービスからの自動転記
- 収入の記録
- チケット申込のリマインド以外の通知
- 発券開始日のリマインド
- リマインドのタイミングの変更
- 日本円以外の通貨と、日本時間以外の時間帯
- 複数端末での同期
- 複数の Gmail アカウントの連携
- ユーザーによるカテゴリの追加
